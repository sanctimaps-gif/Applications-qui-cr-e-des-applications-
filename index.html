Votre projet

Comment ça marche, sans IA ?

Votre phrase est analysée par des règles de grammaire explicites : ce qu'elle nomme, elle l'obtient. Pour tout le reste, un référentiel prend le relais — ce que contiennent réellement les sites et les applications de ce type. « Un site pour mon restaurant » connaît ses sections ; « un carnet de contacts » connaît ses champs. Vous n'avez donc rien à énumérer.

Le référentiel complète, il ne contredit jamais : un champ que vous nommez l'emporte toujours, et « juste », « seulement » ou « uniquement » le désactivent entièrement. Ce qui a été déduit vous est dit, jamais deviné en silence.

Le projet est ensuite assemblé à partir de blocs éprouvés. C'est déterministe : la même phrase donne toujours exactement le même résultat, correct par construction.

Une application n'est pas une maquette : sa logique métier vit dans store.js, séparée de l'affichage — validation, persistance, recherche, tri, statistiques, export CSV — et le projet livré contient ses propres tests, que vous pouvez lancer avec npm test.

Aucun modèle de langue n'est appelé, ici ni ailleurs. Les deux moteurs (web/moteur.js et web/moteur-app.js) sont des fichiers lisibles que vous pouvez ouvrir.

L'onglet GitHub envoie ensuite le projet sur votre dépôt, en un seul commit, par l'API Git de GitHub. Votre jeton reste dans cet onglet : il part chez api.github.com et nulle part ailleurs, et n'est conservé que si vous cochez la case.

Ce que vous venez d'utiliser

      

        Un générateur de sites et de vraies applications qui n'appelle
        aucune intelligence artificielle : ni la mienne, ni celle d'un autre. Pas
        de clé d'IA, pas de compte, pas de quota. Tout est calculé dans cet onglet ; la seule chose
        qui sorte, c'est votre projet, quand vous le publiez sur votre dépôt
        GitHub — directement vers api.github.com, sans serveur intermédiaire. Ce qui
        est produit est lui aussi autonome : aucune police distante, aucun script tiers, aucune
        image chargée depuis l'extérieur, aucune dépendance à installer.
      

      

        Une application est livrée avec sa logique métier isolée dans store.js et sa
        propre suite de tests. Publiez-la sur votre dépôt GitHub en un commit, puis ouvrez-la
        là-bas : clonez, ouvrez index.html d'un double-clic, ou lancez
        npm test. Avec GitHub Pages activé, elle tourne directement en ligne.
      

      

        Le même moteur s'utilise en ligne de commande, avec l'atelier qui modifie un projet
        existant (« ajoute une galerie », « ajoute un champ priorité », « passe en API »,
        « teste », « annule ») :
      

      
git clone https://github.com/sanctimaps-gif/Applications-qui-cr-e-des-applications-.git
cd Applications-qui-cr-e-des-applications-
python3 -m brain atelier --projet ./mon-projet
